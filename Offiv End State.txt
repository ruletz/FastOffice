The End State
Rust binary → Skia/Direct2D rendering → GPU → screen. No browser. No V8. No DOM. No 186MB Chromium DLL.

Your app becomes something like:

~15MB total (Rust binary + Skia + fonts)
<100ms cold start to pixels on screen
~30MB RAM for a document
Text on screen in the time it takes CEF to even start loading
The Path (in order)
Phase 1 — OOXML Parser (Rust, native, not WASM)
You already started this but it's targeting WASM, which still requires a browser host. Flip the target to native. The parser needs to:

Unzip DOCX/XLSX/PPTX (they're ZIPs)
Parse the XML content parts
Build an in-memory document model
Dependencies: zip, quick-xml (not regex — real XML parsing), serde

Phase 2 — Layout Engine
This is the hard part. Take the document model and compute where every character, paragraph, table cell, image goes on screen. Word/paragraph/page breaking, styles cascade, table layout. This is what sdkjs (129MB) mostly does today.

Phase 3 — Renderer (Skia or Direct2D)
Take the layout and paint it. Skia is what Chrome itself uses internally — you'd just be cutting out all the web layers above it. tiny-skia for CPU, skia-safe for GPU-accelerated.

Phase 4 — UI Shell
The toolbar, file picker, dialogs. Options:

winit + egui (pure Rust, lightweight, ~2MB)
tauri (if you want HTML for UI but Rust for logic — still uses WebView but it's the system one, not bundled)
Raw Win32 API (smallest possible, most work)

we can load some things while the user is idle
